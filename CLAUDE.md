# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A research project (no package, no build, no tests) that turns PMI project-management standards — *PMBOK 7th Edition* and the *Practice Standard for Project Risk Management*, expected in `data/corpus/`, not distributed — into a knowledge graph / OWL ontology, and then into embeddings and GNN models for concept retrieval and recommendation.

All code lives in five standalone Jupyter notebooks under `notebooks/`, numbered in pipeline order. There is no shared module: helper functions (`preprocess_text`, `extract_text`, `correct_extraction_mistakes`, `extract_semantic_relations`, …) are redefined per notebook, sometimes with different behavior. When changing one, check whether the sibling notebooks carry their own copy.

## Environment

The notebooks were authored on **Kaggle**, and every I/O path is hardcoded to `/kaggle/input/<dataset>/...` (read) and `/kaggle/working/...` (write). Running locally requires rewriting those paths — the PDFs live in `data/corpus/` (gitignored) and are the files referenced as `/kaggle/input/rm-practise/...` and `/kaggle/input/pmi-practise/...`. The intermediate CSVs (`Concat.csv`, `finalDF (1).csv`, `definitions.csv`, `htt.csv`, `first_version.csv`) were Kaggle datasets and are **not** in this repo; a notebook downstream of one of them cannot run until it is regenerated by the upstream notebook.

Dependencies are installed by `!pip install` cells inside each notebook; `requirements.txt` lists the same set, unpinned. Heavy stack: `spacy` + `en_core_web_sm`, `nltk` (stopwords/wordnet), `stanza`, `transformers`, `sentence-transformers`, `torch`, `torch-geometric`, `pykeen`, `node2vec`/`gensim`, `owlready2`, `rdflib`, `networkx`, `pdfplumber`/`PyPDF2`/`PyMuPDF`.

## Pipeline across the notebooks

The notebooks form a rough sequence; each writes CSV/OWL artifacts the next one consumes.

1. **`notebooks/01_risk_standard_preprocessing.ipynb`** — PDF → clean text. Splits the risk-management standard into its nine processes by section marker (`extract_text(text, "4.1", "5.1")`), strips headers/footers/TOC, fixes ligature damage from PDF extraction (`correct_extraction_mistakes` maps `de nes`→`defines`, `speciﬁ c`→`specific`, …), then sentence-tokenizes into per-process DataFrames and extracts SVO/grammatical/semantic relations with spaCy dependency parses.
2. **`notebooks/02_pmbok_ontology_construction.ipynb`** — the largest notebook and the ontology core. Same preprocessing over PMBOK 6, plus rule-based extraction ("is a / has a", subject-predicate-object with compound nouns), spaCy `Matcher` patterns, TF-IDF retrieval evaluation, then **Phase 4 OWL**: classifies entities into concepts / individuals / data properties / object properties and materializes them with `owlready2` into `Ontology_PMBOKV2.0.owl`, annotates each process with inputs / tools-and-techniques / outputs, and ends with a keyword-based `Recommande()` retrieval function that maps answers back to PDF page numbers via the figure/section tables.
3. **`notebooks/03_concept_definitions_and_triplets.ipynb`** — concept definitions and triplets. Fine-tunes GPT-2 (`gpt2-medium`) on the extracted risk corpus to generate definitions per concept, then runs **REBEL** (`Babelscape/rebel-large`) with a `KB` class that dedupes relations, producing the `head / type / tail` triplet table saved as `htt.csv` / `data_final_pmi.csv`.
4. **`notebooks/04_graph_embeddings_transe_gnn.ipynb`** — triples → embeddings. Builds a `networkx.DiGraph` and a PyKEEN `TriplesFactory` from `Concat.csv` (columns `Concepts`, `Type_relation`, `Concept_of_type_relation`, `Definition`, `Synonym`, `Reference`, `Process_name`), trains **TransE** (dim 64, 80/10/10 split), evaluates with `RankBasedEvaluator`, attaches entity embeddings as node features, and trains `DeepReasoningGNN` (4 × `GCNConv`, three heads for definition/synonym/relation). Exports `graph_data.graphml` and `deep_reasoning_gnn_model.pth`.
5. **`notebooks/05_graph_embeddings_node2vec_gnn.ipynb`** — the alternative embedding route on `finalDF (1).csv`: RDF graph via `rdflib` → 3D Plotly visualization → **node2vec** node embeddings + edge embeddings (`average` / `hadamard` / `weighted_l1` / `weighted_l2`) → sentence-transformer (`paraphrase-MiniLM-L6-v2`, 384-d) embeddings of `Definition`/`Process_name` as node features → a 2-layer `GCNConv` model.

## Conventions worth preserving

- The canonical triple schema is the CSV column trio `Concepts` / `Type_relation` / `Concept_of_type_relation`, carried through every stage; node identity is the concept string with spaces replaced by `_` when it becomes a URI.
- Node/edge indices are derived with `list(G.nodes()).index(...)` inside per-row loops — correct but O(n²); node insertion order is therefore load-bearing, don't reorder graph construction without also fixing the index lookups.
- Markdown cells carry the write-up (mixed French/English) explaining each phase — keep them in sync when changing the code below them.
- Notebook outputs are committed (files are multi-MB); avoid gratuitous re-execution that rewrites large outputs.
